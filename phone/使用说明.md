# OPPO Android 12 本地定时亮屏脚本

适用：未 root 的 Android 12 手机，AutoJs6 本地执行。编写日期：2026-10-19。接口按 AutoJs6 v6.7.0 的官方文档和源码核对；已经过电脑端模拟测试，**尚未在你的 OPPO 实机验证**。

## 文件与默认行为

| 文件 | 用途 |
| --- | --- |
| `run.js` | 主程序；配置位于开头的 `CONFIG` |
| `stop.js` | 向主程序发送停止请求，只影响本项目会话 |
| `inspect-app.js` | 名称识别失败时，获取前台应用包名 |
| `logs/` | 第一次运行后自动生成，按手机本地日期保存日志 |

默认：等待 10 秒 → 打开飞书 → 保持亮屏约 3 分钟（含启动时间）→ 释放亮屏并退出。应用不被强制关闭；系统随后按原来的息屏规则工作，不保证立即黑屏。

主程序不会操作应用内的聊天、消息、考勤或页面；默认不产生滑动。唯一可选手势是 `unlockSwipe` 开启时，对**无安全密码的锁屏**进行一次上滑。

脚本不会修改系统亮度或息屏时间。亮屏机制采用 AutoJs6 的有限时长唤醒锁，正常/异常退出时主动释放，系统超时提供额外上限。不要同时运行其他常亮脚本，以免影响判断。

## 1. 安装 AutoJs6

1. 在手机打开 [AutoJs6 v6.7.0 官方发布页](https://github.com/SuperMonster003/AutoJs6/releases/tag/v6.7.0)。
2. 不清楚手机 CPU 架构时选择名称含 **universal** 的 APK；通常 arm64-v8a 包也适用于较新的 OPPO，但以手机实际架构为准。不要下载 Source code 当安装包。
3. 按系统提示允许用于下载/安装的应用安装 APK，安装后打开 AutoJs6。
4. 把压缩包解压，将整个 `phone` 文件夹复制到手机的一个固定目录，例如内部存储 `Download/cell-phone-automation/phone/`。
5. 在 AutoJs6 文件列表中找到该目录，或使用它的导入功能导入三个 `.js` 文件。文件管理器里直接点击 JS 不一定会由 AutoJs6 执行，应从 AutoJs6 中运行。

手机路径只是示例，实际可以放到 AutoJs6 能访问的目录。若通过“导入”生成了副本，以 AutoJs6 实际运行的那份为准：后续修改配置、定时绑定和查找日志都使用同一份文件。建立定时任务后不要移动主文件。

## 2. 首次权限和手机设置

在手机上手动完成以下设置；ColorOS 小版本会改变菜单名称，找不到时使用系统设置搜索。

- **开启 AutoJs6 无障碍服务**：在“无障碍/辅助功能 → 已下载的服务”一类入口中启用；这是识别当前应用和可选锁屏滑动的必要条件。脚本发现未启用会报错退出，不会无限等待授权。
- **按应用提示允许文件访问**，确保可以读取脚本和写入同目录的日志。
- **后台运行相关设置**：为 AutoJs6 允许后台活动、自启动（若有），按需取消其电池优化；若应用提供前台服务/运行通知选项，开启以方便查看和停止。最近任务卡片锁定可以作为辅助，不能视为系统不会回收的保证。
- **后台弹出界面/悬浮窗权限**：若测试时只记录了 START 而目标应用未显示，检查 AutoJs6 的“显示在其他应用上层”和 ColorOS 的后台弹出界面权限。本脚本不创建悬浮窗，但运行器的后台启动可能需要这类授权。是否足够必须实测。
- **定时阶段的“闹钟和提醒”访问**：在系统特殊应用访问权限中查找 AutoJs6，或从其定时任务页面按提示设置。以应用实际提供的入口为准。
- 接通电源并检查手机日期、时区。计划按**手机本地时间**判断；在中国使用时设为北京时间/上海时区。
- 第一次测试先人工解锁、登录目标应用，并处理首次启动提示或升级弹窗。

为了验证脚本自己的常亮效果，**先关闭开发者选项的“充电时保持唤醒/不锁定屏幕”**，将系统自动息屏设为较短时间，如 30 秒。否则无法判断是否由脚本维持亮屏，结束后也可能一直不灭。不要开启“不要保留活动”或把后台进程限制设为零。

不需要 root、电脑持续连接、USB 调试、截图权限、通知读取权限或“修改系统设置”权限。

## 3. 先运行 3 分钟测试

在 AutoJs6 编辑 `run.js`，仅按需修改开头两项：

```javascript
targetAppName: "飞书", // 钉钉用户改为 "钉钉"
targetPackage: "",   // 先留空
```

保持 `mode: "test"`、`testDurationMinutes: 3`、`testStartDelaySeconds: 10`。

1. 手机已解锁，目标应用已登录。
2. 在 AutoJs6 中点击运行 `run.js`。
3. 看到倒计时提示后，10 秒内按 Home 返回桌面。这样可以验证从后台打开应用。
4. 应当在倒计时结束后打开目标应用，并在这 3 分钟内保持屏幕亮着。此时不用手动点击屏幕。
5. 看到结束提示后再等待原来的息屏超时。屏幕通常恢复自动关闭，但若目标应用自身要求常亮，仍可能不关闭。

测试通过标准：应用自动进入前台，超过原本 30 秒超时仍亮屏，到时日志出现 `END COMPLETED`。日志里的 `FOREGROUND_CONFIRMED` 只表示检测到目标包名，不证明已经登录或位于某个特定页面。

如果应用名称识别失败：运行 `inspect-app.js`，8 秒内手动切到目标应用。之后回 AutoJs6 查看日志，或打开同目录的 `detected-app.txt`，将得到的包名填入 `targetPackage`。填写包名后优先使用包名，不再按名称查找。应用分身和工作资料不能仅靠包名区分，第一版请使用个人空间的主应用。

## 4. 熄屏与无密码锁屏测试

先在已解锁状态测试成功，再测试以下情况：

1. 若计划无人值守，取消系统安全密码，并检查目标应用自身没有应用锁；保留密码也可以手动解锁后运行，但到点处于安全锁屏时脚本会失败退出。
2. 若取消密码后仍需要上滑进入桌面，将 `unlockSwipe: false` 改为 `true`。
3. 保持测试倒计时为 10 秒，运行后在倒计时内按电源键熄屏，等待脚本唤醒。
4. 脚本仅在检测到无安全密码的锁屏时尝试一次上滑；不能解锁就停止。不要填写或自动输入锁屏密码。

运行中再次按电源键熄屏，脚本会在检查时停止，不主动把屏幕重新点亮。若机器的锁屏布局不适用默认上滑方向，需要实机调整，不能从电脑模拟测试判断。

## 5. 先测一次定时，再配置每天运行

### 一次性启动测试

保持 `mode: "test"`，把 `testStartDelaySeconds` 改为 `0`。在 AutoJs6 的脚本菜单/定时任务页面，为**这份 `run.js`**新建“仅一次/一次性”任务，时间设为当前时间之后 2–3 分钟，执行一次，不开启脚本循环。保存后返回桌面或熄屏等待。

这一步验证 AutoJs6 的定时调度与后台启动是否可用。日志完全没有新增 START，多半是未触发；有 START 但随后报错，则查看具体错误。具体页面入口随版本和语言变化；官方实现提供一次性、每日和每周任务。

### 正式固定时段

例如周一到周五 09:00–10:00：修改 `run.js` 配置：

```javascript
mode: "window",
schedule: {
    start: "09:00",
    end: "10:00",
    weekdays: [1, 2, 3, 4, 5]
},
```

再为 `run.js` 新建每周定时任务，选择周一至周五、09:00，执行一次。**脚本配置决定允许运行的时段，AutoJs6 定时任务负责触发，两处需要对应。** 配置文件本身不会注册闹钟；不要只改时间然后退出。

- 09:00 触发，持续至 10:00。
- 如果系统延迟到 09:07 才触发，仍在 10:00 结束。
- 10:00 或之后触发，会跳过，不额外补跑一小时。
- 工作日窗口内手动运行也会执行到 10:00；因此修改配置后不要在不打算启动时随意点击运行。
- 可配置跨午夜，如周五 23:00–次日 01:00，星期以**开始日**为准。
- 修改窗口时，同步修改 AutoJs6 触发时间和星期，删除旧任务，避免重复触发。
- “周一到周五”不是法定工作日历，不会自动识别节假日和调休。

建议先将窗口设置为“几分钟后开始，再过 3 分钟结束”并创建一次性任务，验证结束边界后再使用真实日程。

脚本不包含开机重建任务或权限自动恢复。重启、升级、系统强行停止 AutoJs6 后，要重新打开 AutoJs6，检查无障碍与任务状态，再做一次短时定时测试；不能假定重启恢复已可靠。

## 6. 停止、日志与故障排查

**停止当前任务**：在同一个 AutoJs6 中运行 `stop.js`；正常轮询会在约 1 秒内处理（若正在调用系统 API，可能稍后处理），以 `END STOPPED` 为准。也可以在 AutoJs6 运行管理中直接停止 `run.js`。停止当前会话不会删除之后的定时任务；要停用每日运行，还需禁用/删除其定时任务。

本脚本在你持续切到其他应用超过 10 秒时也会停止。打开 AutoJs6 看日志、拉下通知栏或系统界面可能影响前台识别，因此观察长时间运行时尽量不要操作手机。若需要更长宽限，可将 `foregroundGraceSeconds` 改为 30。它不会反复把目标应用拉回前台。

查看同一脚本目录下 `logs/年-月-日.log`，或 AutoJs6 自带日志。日志行时间是 ISO UTC（尾部 Z），`LOCAL_TIME` 行同时记录手机本地时间；文件名和配置时间都按手机本地日期/时区。日志不记录屏幕文字或聊天内容。

| 日志/现象 | 处理办法 |
| --- | --- |
| 没有 START | 检查定时任务是否启用、绑定路径、系统时间、闹钟访问和后台限制 |
| SKIPPED | 检查 mode、星期、起止时间；窗口外退出属于预期行为 |
| 无障碍服务未开启/断开 | 回系统设置重新启用，再手动重试 |
| 找不到目标应用 | 检查名称；使用 inspect-app.js 获取实际包名 |
| 未确认目标应用进入前台 | 检查后台拉起权限、应用锁；确认运行时手机没有安全锁屏 |
| 仍有滑动锁屏 | 先手动解锁验证，之后按需启用 unlockSwipe |
| 屏幕已关闭 | 若非主动按电源键，说明常亮方式在当前环境未通过；保存日志继续诊断，不直接增加盲目滑动 |
| AWAY 后 ERROR | 通知、系统界面或其他应用持续占据前台；回看日志中的包名 |
| DUPLICATE | 已有同项目脚本运行；等待或运行 stop.js 后再试 |
| RECOVER | 上次异常终止留下状态，但系统文件锁已释放；本次自动覆盖残留记录 |
| 结束后不息屏 | 查看充电常亮开关、其他常亮应用、目标应用自身行为；本脚本不强制锁屏 |
| stop.js 发送请求却无 END | 可能是主脚本已被系统终止留下记录；查看 AutoJs6 运行管理，必要时停止 run.js |

日志按天追加，长期使用可定期手动删除旧日志。停止脚本不能由另一个 Auto.js 变体代替执行，因为会话状态存放在当前 AutoJs6 的私有目录。

## 7. 建议记录的验收结果

依次通过：手动 3 分钟、熄屏唤醒、2–3 分钟后的定时启动、正式窗口结束、stop.js 停止、接电闲置一晚后启动。记录机型、ColorOS 构建号、AutoJs6 版本、目标应用版本和对应日志。只有实机多次通过后，才把该组合视为可无人值守使用。

目前没有实现周期性应用内手势、自动登录、每日自动重试、远程控制或状态上报。亮屏/前台不等于目标应用服务端认定的在线状态。
